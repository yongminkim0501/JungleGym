# 자동 퇴실과 운동 시간

- 한국 시간 새벽 **04:00**를 운영일 마감으로 사용한다.
- 마지막 마감 이전에 입실했고 아직 퇴실하지 않은 기록을 자동 종료한다.
- 기본적으로 입실 후 **120분**이 지나야 자동 종료한다. 03:40 입실자는 04:00에 종료하지 않고 05:40부터 종료 대상이 된다.
- 정확히 04:00 이후 입실한 기록은 다음 운영일에 속한다.
- Spring 스케줄러가 매분 확인한다. 재시작 후에는 놓친 기록도 다음 실행 때 정리한다.
- 자동 퇴실의 운동 시간은 입실 시각과 관계없이 **59분**이다. 직접 퇴실은 실제 경과 시간을 분 단위로 내림해 사용한다.
- `checkedOutAt`은 시스템이 실제 종료를 처리한 시각이다. 운동 시간은 이 시각에서 역산하지 않고 API의 `durationMinutes`를 사용한다.
- 자동 종료 여부는 `autoCheckedOut`으로 구분한다. 입실 중인 기록은 `durationMinutes: null`이다.
- 출석은 기존과 같이 한국 시간 입실 날짜에 귀속한다. 제목·사진은 자동 종료로 수정하지 않는다.
- 마이페이지 입퇴실 기록에 `자동 퇴실` 표시와 `59분`을 함께 보여준다.

예: 09/30 11:30 입실 후 퇴실을 누르지 않으면 10/01 04:00 이후 배치에서 종료하고 운동 시간은 59분이다.
09/30 23:40 입실 후 10/01 01:00 직접 퇴실하면 실제 운동 시간 80분이다.

## 환경변수

| 변수 | 기본값 | 의미 |
| --- | --- | --- |
| `AUTO_CHECKOUT_ENABLED` | `true` | 자동 퇴실 스케줄러 실행 |
| `AUTO_CHECKOUT_GRACE_MINUTES` | `120` | 입실 직후 보호 시간. `0`이면 04:00 마감 시 유예 없이 종료 |

서버는 먼저 Flyway V3로 `auto_checked_out` 필드와 조회 인덱스를 추가한다. 기존 기록은 수동 퇴실로 유지된다.
프론트는 이전 서버의 응답에서도 동작하도록 자동 퇴실 여부 기본값을 false로 처리하고, 운동 시간 필드가 없으면 직접 퇴실 시간을 계산한다.
운영 중 도입 시에는 오래된 미퇴실 기록도 대상이 되므로 필요하면 첫 기동에 `AUTO_CHECKOUT_ENABLED=false`로 설정해 기록을 먼저 검토한다.

동시 실행은 `checked_out_at IS NULL` 조건의 원자적 갱신으로 처리한다. 직접 퇴실이 먼저 완료되면 자동 종료가 덮어쓰지 않는다.
자동 종료가 먼저 완료되면 직접 퇴실 요청은 기존 `NOT_CHECKED_IN` 응답을 받는다.
